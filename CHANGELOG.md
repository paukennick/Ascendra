- REQ-251 (learner-facing; FAIL-1660 to FAIL-1662): **Generated lesson and Quiz-me questions are asked more firmly to keep answer choices even**, so the right answer is less often the longest option and wrong options less often give themselves away with words like "always" or "only". The 2026-11-12 pre-generation trial had these style findings on 22 of 25 first drafts although the rules already forbade them: the prompt said "parallel in length" with no number, named four of the eight cue words the check uses, and gave the right answer nowhere to put its qualifications. The item-writing rules (lesson practice, Quiz-me, review and exam items), the option fields' schema descriptions and the JSON template now state the check's own limits (the right answer at most 1.25 times the average wrong-option length or 8 characters more, aiming for it not to be the longest; none of always, never, only, all, none, every, guaranteed, completely in a wrong option), from one module the check also reads (`lib/item-style.ts`); say options are short answers with qualifications in the explanation; and add a good/bad example and a check to run on each option set. The one steered retry now names a target ("shorten the right answer to at most N characters, or lengthen the wrong options to about M"; "make it wrong through its content"). Two false positives of the check are fixed: a right answer that is not longer than every wrong option is not "much longer" (FAIL-1660), and "every" in an interval such as "every 2 hours" is not a cue word (FAIL-1661). The cached system block is unchanged. New `npm run items:style -- <files or dirs>` scores stored or generated question JSON with the same check and prints the rates by kind (no model, no database); on the 32 stored lessons from the 2026-11-09 audit it reports 84% with a style finding and the right answer longest in 45 of 64 option sets, the same under the old and new check. Nick's decision (2026-11-12, "Let the model think"; FAIL-1663): the practice half is now written with bounded thinking so the model can check each option set before writing it, which it could not with thinking off. The 5.5 models take no thinking-only budget (`budget_tokens` is a 400), so the bound is effort `low` (soft) and `max_tokens` = 6,000 for the answer plus a named 4,000-token thinking allowance (`PRACTICE_THINKING_BUDGET_TOKENS`, lib/lesson-generation.ts), a hard cap that leaves the answer its whole room however much the model thinks (a practice answer is about 4,800 tokens), so the 2026-09-29 failure where thinking used the whole cap (FAIL-008) cannot come back that way; if a reply still stops on `max_tokens`, the app writes it once more with thinking off. One configuration (`PRACTICE_CALL`) is used by the app's generator and its retry, pre-generation's batch request and live retry, and the live eval; the teaching text stays thinking off. Pre-generation's upper bound prices the thinking: about $0.255 a lesson (was $0.195), $227.83 for the 886-lesson launch set on a fresh seed (was $172.79); a 25-lesson trial needs `max_usd` 7.
